# Grounded Q&A evaluation, 2026-10-22 (offer)

Model under test: `gemini-3.5-flash-lite`.

25 answerable and 18 unanswerable questions over the 17-clause job offer fixture. Real Gemini, real Postgres, and the real citation check. Questions were written before any results were seen and not tuned afterward, as the note at the top of offer_fixture.py describes.

## Answerable questions

| Outcome | Count |
|---|---|
| Cited the right clause | 100% (25/25) |
| Cited a wrong clause | 0% (0/25) |
| Wrongly abstained | 0% (0/25) |

Of the wrong abstentions, 0 were our citation check rejecting the model's quote, the rest were the model itself saying the document didn't cover it.

## Unanswerable questions

| Outcome | Count |
|---|---|
| Correctly said it couldn't find it | 100% (18/18) |
| Hallucinated an answer | 0% (0/18) |

## Latency

Mean 2.8s per question, slowest 42.2s.

## Every miss

None.

## Caveats

- 43 questions is a small sample, a difference of one or two is not strong evidence.
- The fixture is 17 short, clean clauses. Real contracts are longer and messier.
- Clause identity is decided by exact clause text, so a clause that repeats another word for word could be credited to the wrong key.

## What changed between the first run and this one

An earlier run on October 22 (recorded in the commit before this one, "Record the first question answering run on the
job offer fixture") scored 17 of 18 on the unanswerable questions. One was flagged, "Which days of the week can I
work from home?": the clause gives a number of days and no weekdays, and the model answered with the number of days.
The question was left as written. The answering instruction then gained a rule, "answer the question that was asked,
not a nearby one: if the clauses give only a related fact and not the specific detail asked for, the document does
not cover it", and this run is with that rule. It scored 18 of 18, and the 25 answerable questions were still all
answered with the right clause, so the rule did not make the model refuse anything it should answer here.

It is one run on 43 questions. That the flagged question disappeared is evidence for the rule, not proof, since a
model can answer differently from one run to the next. The same rule was run on the loan and lease fixture to look
for false refusals there (see qa-2026-10-22.md).
